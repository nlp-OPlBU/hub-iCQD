# 网络研究与报告

## 企业 ESG 月报

确定客户全称、股票代码、主要业务、上市地和观察期。日期未指定时，按北京时间回溯一个月。同步检索适用的政策、评级与标准，行业数据与实践，客户公司披露及可比企业行动。煤炭、电力和煤化工客户可参考 [ESG 月报检索与编辑参考](references/esg-example.md)。

报告按「管理摘要」「政策、评级与标准」「行业动态与最佳实践」「客户动态与 ESG 影响」「同业对标与行动建议」展开。评级条目给出机构与日期，标准条目注明征求意见、研制或实施状态。针对客户事项逐一说明适用主体、环境／社会／治理影响，给出建议责任部门、完成时间或触发条件及跟踪指标。对标案例注明披露主体、统计期和可迁移做法。

## 确定问题和检索范围

从请求提取交付目标、受众、研究对象、时间和地区范围、比较维度。按主题确定同义词、正式名称、常见缩写、原文语言和最可能持有一手证据的机构。近期或历史任务写明绝对日期及必要的时区，分别核对发布日期、事件日、数据期和生效日。仅在无法从上下文解决且歧义会显著改变研究结果时提问。

把问题拆成少量可独立验证的检索组。每组先做覆盖面搜索，再用机构域名、文件号、指标名、原文关键词或反例补查。按需并行提交独立查询。保留使用的时间口径，避免只用一个关键词或只读同一来源的转载。

## 搜索 筛选 核验

1. 使用本环境可用的联网搜索和页面读取工具。适合批量运行且已有 Brave 凭据时，可调用 [search_web.py](scripts/search_web.py) 按组搜索。否则用内置联网工具，候选结果可导入相同结构。读取[脚本用法](references/scripts.md)获取命令、输入和输出格式。
2. 来源较多时，用 [triage_sources.py](scripts/triage_sources.py) 对候选 URL 去除常见追踪参数、按组去重并排序，保留日期冲突和任务错误。排序只决定优先阅读顺序。按相关性、证据权威性、内容时效和信息增量再挑选。不同网址的转载按其共同原始来源去重。
3. 打开拟引用的原文，记录直接 URL、发布主体和日期、事件日期或数据期、可支持的事实及限定条件。用适合该问题的主管机构、统计机构、研究原文、技术维护方或当事方披露核验关键结论。搜索摘要用于找线索。首选来源打不开时，查原始文件的可靠镜像或独立证据，并说明影响。
4. 对重要且有争议的结论查证反例、更新、适用范围和独立来源。互相转载不算交叉核实。明确区分已证实事实、来源方主张、推断和建议。一个维度缺证据时，换关键词、来源或语言补查。关键缺口仍存在时，在结果中注明查证范围和限制。

## 整理与交付

先写能直接回答研究问题的结论，再按用户关心的维度展开。给出可比较的数据口径、必要的取舍或影响。若用户需要决策支持，提出与证据对应的行动、触发条件或后续验证指标。把直接来源放在相关陈述附近，标明预测、草案、估算与已发生事项的状态。

先综合读过的证据再写报告。用 [render_report.py](scripts/render_report.py) 把审核过的结构化简报生成 Markdown，校验事实和分析条目有来源引用，并生成链接及来源索引。篇幅短或用户需要其他格式时，可直接作答或生成相应文档。交付前核对主要数字、时间、主体、引用与结论是否一一对应。联网受限时交付能够核验的部分并说明局限。

无脚本模式使用网页工具并直接撰写报告，由代理去重、判断日期和核对引用。有脚本模式按[脚本用法](references/scripts.md)执行批量检索、候选整理及报告渲染。两种模式沿用相同的证据口径。
