# 多轮对话与历史持久化决策

## 当前决定

当前版本实现页面生命周期内的多轮追问，不持久化会话历史。

- 浏览器保留本次页面中的消息，并向 API 发送最近 5 个成功轮次。
- 历史只包含问题、答案摘要和 SQL，不包含完整查询结果。
- `conversation_id` 标识一次页面内对话，`request_id` 标识单次 Agent 运行。
- 刷新页面或点击“新建对话”会清空上下文。

## 暂缓持久化的原因

系统当前没有用户身份、访问控制和会话所有权模型。直接保存问题、SQL
及查询结果会让不同使用者之间的数据隔离无法保证，也会增加保留期限、删除、
脱敏以及与 LangSmith trace 重复存储等治理问题。因此，不把只读业务数据库
`chinook.db` 用作会话库，也不开放历史查询 API。

## 重新评估条件

满足以下条件后再实现 `/chat/:conversationId` 和服务端历史：

1. 产品验证多轮追问确有持续使用价值，而不只是演示需求。
2. 明确登录方式、用户或租户标识及会话 ACL。
3. 确定数据保留期限、用户删除能力和日志/trace 脱敏策略。
4. 使用独立 SQLite/Postgres 存储 `conversations`、`messages` 和必要的
   `agent_runs` 摘要，不保存完整结果集。
