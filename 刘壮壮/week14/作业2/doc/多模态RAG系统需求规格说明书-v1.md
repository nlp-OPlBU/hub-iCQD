# 多模态 RAG 系统需求规格说明书

**版本：** V1.0  
**状态：** 需求基线初稿  
**适用范围：** 第一版（个人使用）  
**项目类型：** 基于 PDF 知识库的多模态 RAG 问答系统

---

# 1. 项目概述

## 1.1 项目背景

本项目计划自主开发一套多模态 RAG（Retrieval-Augmented Generation，检索增强生成）系统。

系统以 PDF 文档作为主要知识来源，通过 MinerU 完成 PDF 解析，使用 Elasticsearch 实现关键词与向量混合检索，并通过支持视觉输入的多模态大语言模型完成知识问答。

用户可以上传 PDF 文档，也可以在提问时上传图片。系统结合知识库内容、历史对话和用户图片，生成支持图文混排的回答，并提供知识来源引用。

## 1.2 项目目标

第一版主要实现以下能力：

1. PDF 文档上传、存储和管理。
2. 基于 Kafka 的异步 PDF 解析任务处理。
3. 使用 MinerU 解析 PDF，提取文本、页面结构和图片。
4. 使用 Elasticsearch 建立关键词和向量混合检索能力。
5. 支持连续多轮对话和历史上下文管理。
6. 支持用户上传图片并进行多模态问答。
7. 支持 PDF 来源引用及原文定位。
8. 提供基础系统管理、健康检查、日志和统计功能。
9. 提供 REST API，为未来其他客户端调用预留能力。

## 1.3 用户范围

第一版仅供个人使用。

- 不建设注册、登录和多用户管理系统。
- 使用基础接口访问认证和权限校验。
- 不建设面向公众的 SaaS 平台。
- 不建设完整的第三方 API 开放平台。

## 1.4 第一版设计原则

- 优先保证核心业务链路完整。
- 优先保证文档、任务、索引和对话数据的一致性。
- 控制第一版开发复杂度。
- 核心业务模块保留必要的扩展接口。
- 不为了未来可能出现的需求提前建设复杂平台功能。

# 3. 技术选型约束

以下为目前确定的第一版技术方向。

| 组件 | 选择 | 职责 |
|---|---|---|
| 后端 | FastAPI | REST API、业务逻辑 |
| 消息队列 | Kafka | PDF 异步解析任务 |
| PDF 解析 | MinerU | PDF 内容解析 |
| 关系型数据库 | SQLite | 对话、文档、任务及业务元数据 |
| 检索引擎 | Elasticsearch | BM25、向量检索 |
| Embedding | BAAI/bge-small-zh-v1.5 | 文本向量生成 |
| 多模态 LLM | DeepSeek Flash | 文本和图片理解、回答生成 |
| Redis | 第一版非必需 | 暂不作为核心依赖 |

### 3.1 DeepSeek Flash

第一版采用 DeepSeek Flash 作为统一多模态模型。

API 基础地址：

`https://api.deepseek.com`

模型标识：

`deepseek-flash`

调用方式采用 OpenAI 兼容接口。

图片输入采用 Base64 编码方式，将文本和图片组织在同一条多模态消息中。

官方视觉能力文档：

https://api-docs.deepseek.com/zh-cn/guides/vision

具体 API 请求参数、图片大小限制、Token 计算和流式返回格式在技术接入阶段进一步验证。

### 3.2 Redis

Redis 不作为第一版必需组件。

第一版不得将核心业务流程设计成必须依赖 Redis 才能运行。未来确有缓存、限流或其他明确需求时，再评估是否引入。

# 4. PDF 上传与文档管理

## 4.1 文件上传要求

支持格式：

- PDF。

上传限制：

| 项目 | 限制 |
|---|---|
| 单个文件大小 | 最大 100 MB |
| 单次上传数量 | 最多 10 个 |
| 支持格式 | PDF |
| 上传方式 | 点击选择、拖拽上传 |

前端需要：

1. 显示文件上传进度。
2. 每个文件独立展示上传成功或失败状态。
3. 上传失败时支持重新上传。
4. 上传前进行格式、大小和数量检查。
5. 超出限制时给出明确提示。

后端必须再次校验文件格式和大小，不能仅依赖前端验证。

## 4.2 上传成功后的业务流程

PDF 上传成功并保存后：

1. 创建独立的 `document_id`。
2. 保存文档元数据。
3. 创建解析任务。
4. 为任务生成独立的 `task_id`。
5. 将任务发送到 Kafka。
6. 初始解析状态设置为 `pending`。

上传成功后自动创建解析任务，不需要用户手动点击开始解析。

上传失败时：

- 不创建有效文档记录。
- 不创建有效解析任务。
- 用户可以重新上传。

## 4.3 文档列表

文档列表至少展示：

- PDF 文件名。
- 文件大小。
- 上传时间。
- 解析状态。
- 解析开始时间。
- 解析完成时间。
- 解析进度（MinerU 有可靠进度数据时才展示）。
- 解析失败原因。
- 操作入口。

支持以下操作：

- PDF 预览。
- 重新解析。
- 删除文档。

## 4.4 搜索、筛选与排序

支持：

- 按文件名搜索。
- 按上传时间筛选。
- 按解析状态筛选。
- 按文件名排序。
- 按文件大小排序。
- 按上传时间升序或降序。

默认按照上传时间倒序排列。

## 4.5 解析状态

解析任务状态：

| 状态 | 含义 |
|---|---|
| pending | 等待处理 |
| processing | 正在解析 |
| completed | 解析成功 |
| failed | 解析失败 |

多个 PDF 可以同时排队，实际运行并发由后端控制。

第一版不自动重试解析失败的任务，由用户手动重新解析。

## 4.6 重新解析机制

重新解析必须采用新旧版本隔离机制。

具体流程：

1. 保留当前有效解析版本。
2. 创建新的解析任务。
3. 为新解析结果生成独立版本。
4. 新版本解析成功后，切换当前有效版本。
5. 清理旧版本文件和 ES 索引。
6. 新版本解析失败时，继续使用旧版本。

建议使用 `document_version` 管理解析版本。

第一版只保留当前有效解析版本的完整数据，不长期保存历史解析文件。

历史任务状态、开始时间、完成时间和错误日志可以保留。

前端需要明确展示：

- 重新解析中（旧版本仍可用）。
- 重新解析失败（旧版本仍可用）。

建议区分：

- `document_status`：文档当前是否可用于检索。
- `parse_task_status`：当前解析任务状态。

## 4.7 删除文档

删除文档时，需要删除：

- SQLite 中的文档记录。
- PDF 原始文件。
- MinerU 解析结果。
- PDF 提取图片。
- Elasticsearch 中对应的文本和向量数据。

删除过程中需要考虑正在运行的解析任务。

如果任务无法立即终止，必须确保：

- 删除后任务不能重新写入 ES。
- 删除后不能重新创建有效文档数据。
- 删除的文档不能继续参与检索。

可以通过删除标记、任务版本号或其他并发控制机制实现。

## 4.8 知识库统计

支持当前状态统计：

- 文档总数。
- 解析完成数量。
- 解析中数量。
- 解析失败数量。
- PDF 文件总大小。

不做时间趋势统计。

## 4.9 清空知识库

支持一键清空知识库。

执行前必须二次确认。

清空内容包括：

- 全部 PDF 原文件。
- 文档记录。
- 解析结果。
- PDF 提取图片。
- Elasticsearch 中对应的数据。

需要妥善处理正在运行的解析任务，防止清空后任务重新写入数据。

清空知识库不影响历史对话。

## 4.10 检索范围选择

支持用户选择检索范围：

- 默认检索全部解析完成的 PDF。
- 用户可以选择一个或多个 PDF。
- 未完成首轮解析的文档不能参与检索。
- 解析失败且没有可用旧版本的文档不能参与检索。

第一版不支持多个知识库、知识库分组和标签。

# 5. PDF 解析与数据存储

## 5.1 MinerU 解析

使用 MinerU 解析 PDF。

需要保存：

- Markdown 等解析结果。
- JSON 等结构化解析结果。
- 页面结构。
- 页面文本。
- 文本对应的页码。
- PDF 提取图片。
- 图片对应的页码。
- 图片与相关文本之间的上下文关联。

第一版不支持人工编辑解析结果。

## 5.2 图片生命周期管理

图片分为两种不同的数据类型。

### 用户上传图片

- 属于对话数据。
- 持久化保存。
- 与对应消息关联。
- 删除单轮问答时清理关联图片。
- 删除整个对话时清理该对话图片。

### PDF 提取图片

- 属于知识库数据。
- 与 PDF 文档和解析版本关联。
- 删除 PDF 时清理。
- 重新解析成功切换版本时清理旧版本图片。

两类图片必须保持生命周期隔离。

# 6. RAG 检索系统

## 6.1 检索总体流程

用户问题进入系统后，执行：

1. 接收用户原始问题。
2. 结合历史对话执行 Query Rewrite。
3. 执行 BM25 关键词检索。
4. 执行 Dense Vector 向量检索。
5. 使用 RRF 融合结果。
6. 执行去重和相关性过滤。
7. 获取 Top 5 文本 Chunk。
8. 根据 Chunk 关联补充 PDF 图片。
9. 将检索结果交给多模态 LLM。

## 6.2 Query Rewrite

结合历史对话，将存在省略、指代不清等问题的当前问题改写成独立完整的问题。

规则：

- 原问题完整时不需要改写。
- 改写后的问题仅用于检索。
- 不覆盖用户原始问题。
- 最终回答仍需结合用户原始问题和历史上下文。

## 6.3 混合检索

使用：

- BM25：关键词检索。
- Dense Vector：语义向量检索。
- RRF：融合两路检索结果。

默认最多返回 Top 5 文本 Chunk。

Elasticsearch 负责关键词和向量检索。

## 6.4 检索去重和多样性

- 相同 Chunk 不重复。
- 相邻 Chunk 可以合并或关联展示。
- 尽量避免 Top 5 全部来自同一个 PDF。
- 不强制每个 PDF 都有检索结果。
- 相关性优先。

## 6.5 相关性过滤

支持相关性阈值过滤。

当检索结果相关性不足时，系统应明确告知用户知识库没有足够依据。

不得强行将低相关性内容交给 LLM，并让模型将其解释成可靠来源。

需要注意：RRF 融合分数不等于真实语义相似度。具体相关性判断策略和阈值需要在技术设计及检索评估阶段确定。

## 6.6 Reranker

第一版不使用 Reranker。

保留后续接入接口。

## 6.7 Multi-Query

第一版不使用 Multi-Query。

每次只执行一个改写后的问题对应的一次 BM25 + Dense Vector 混合检索。

## 6.8 无相关资料时的处理

所有用户问题都执行 RAG 检索，不进行意图路由。

即使没有检索到相关 PDF 内容，也允许模型基于正常对话上下文进行回答。

但必须明确区分：

- 来自 PDF 的内容。
- 来自模型自身知识的内容。

不得伪造 PDF 来源引用。

## 6.9 检索详情

用户可以展开查看检索详情：

- 检索耗时。
- 命中 PDF 文件名。
- Chunk 摘要。
- 页码。
- 检索方式（BM25 / Dense Vector）。
- RRF 融合排名。

不展示 Prompt、API Key 等敏感信息。

不提供完整上下文组成查看功能。

# 7. 多模态问答

## 7.1 用户输入

支持：

- 纯文本提问。
- 文本 + 单张图片。
- 文本 + 多张图片。

图片格式：

- JPG。
- JPEG。
- PNG。
- WEBP。

限制：

| 项目 | 限制 |
|---|---|
| 单张图片 | 最大 10 MB |
| 单次提问 | 最多 5 张 |
| 图片保存 | 持久化保存 |

前端超限时提示并阻止提交，后端再次校验。

## 7.2 多模态上下文组织

系统需要组织以下信息：

- 用户原始问题。
- Query Rewrite 结果。
- 历史对话上下文。
- RAG 检索到的文本。
- 用户上传图片。
- 与检索文本相关的 PDF 图片。

统一交给 DeepSeek Flash 处理。

用户上传图片和 PDF 提取图片均需要保留与原始数据的关联。

## 7.3 回答输出

支持：

- Markdown。
- 图文混排。
- 图片插入回答正文。
- 末尾来源引用。
- 流式输出。

回答中的图片应支持查看原始图片。

## 7.4 流式输出与异常处理

正常完成：

- 状态为 `completed`。

用户主动停止：

- 状态为 `stopped`。
- 保留已经生成的内容。

API 失败、网络中断或超时：

- 状态为 `failed`。
- 保留已经生成的部分内容。
- 展示明确错误信息。
- 不自动重试，避免重复消耗 Token。

错误提示：

| 错误类型 | 用户提示 |
|---|---|
| 超时 | 请求处理超时，请重试 |
| 网络中断 | 网络连接异常，请检查网络 |
| API 限流 | 当前请求过多，请稍后重试 |
| 服务异常 | AI 服务暂时不可用，请稍后重试 |

系统内部需要记录：

- 错误类型。
- 具体错误信息。
- 发生时间。
- 关联 `conversation_id`。
- 关联 `message_id`。

## 7.5 重试和修改

支持重新生成回答。

重新生成时：

- 保留用户原始问题。
- 保留用户图片。
- 重新执行生成。
- 替换旧回答。

支持修改 AI 回复。

输入上下文包括：

- 用户原始问题。
- 原 AI 回答，包括已经生成的部分。
- 用户修改要求。

支持编辑用户问题：

- 修改原始问题。
- 重新生成回答。
- 编辑历史问题时，删除该问题之后的全部消息。

# 8. 历史对话管理

## 8.1 基础功能

支持：

- 新建对话。
- 查看对话。
- 切换对话。
- 删除对话。
- 搜索对话。
- 对话置顶。
- 修改对话标题。
- 清空全部历史对话。

每个对话具有独立 `conversation_id`。

每条消息具有独立 `message_id`。

## 8.2 上下文管理

采用：

**最近 N 轮原始消息 + 历史对话摘要。**

- 最近 N 轮保留原始问题和回答。
- 更早的历史压缩成摘要。
- N 的具体数值和摘要生成策略在技术设计阶段确定。

## 8.3 对话标题

- 第一轮问答完成后，由 AI 自动生成简短标题。
- 用户可以随时修改标题。
- 用户手动修改后，AI 不再自动覆盖。

## 8.4 对话置顶

支持置顶和取消置顶。

排序规则：

- 置顶对话在列表顶部。
- 置顶对话内部按照最近活动时间排序。

不支持归档。

## 8.5 对话搜索

支持搜索：

- 对话标题。
- 用户问题。
- AI 回答内容。

点击搜索结果后，跳转到对应对话及具体消息位置。

## 8.6 删除问答

以一轮问答为单位删除。

删除某轮问答时：

- 删除该轮问题和回答。
- 删除该轮之后的所有消息。
- 清理关联的用户上传图片。
- 不影响知识库 PDF 数据。

删除整个对话时：

- 删除全部消息。
- 删除全部关联用户上传图片。
- 不影响知识库数据。

## 8.7 清空全部历史对话

支持一键清空全部历史对话。

执行前二次确认。

删除：

- 所有对话。
- 所有消息。
- 所有关联用户上传图片。

不影响 PDF、解析结果和 Elasticsearch 知识库索引。

## 8.8 导出对话

支持 Markdown 导出：

- 单条 AI 回答。
- 整段对话。

保留 Markdown 格式和来源引用。

## 8.9 其他交互

支持：

- 一键复制完整 AI 回复。
- 点赞。
- 点踩。
- 取消评价。
- 点赞与点踩相互切换。
- 点踩原因可选填写。

评价数据保存：

- 评价结果。
- 评价时间。
- `message_id`。

第一版不建设反馈统计分析页面。

不支持对话分享链接。

# 9. 回答偏好设置

## 9.1 回答风格

支持预设风格：

- 简洁回答。
- 详细解释。
- 教学模式。
- 技术分析。

支持自定义自然语言要求。

例如：

- 结合 Python 代码解释。
- 多使用生活中的例子。
- 尽量从底层原理分析。

## 9.2 回答深度

支持：

- 简要。
- 标准。
- 深入。

回答风格和回答深度是两个独立维度。

## 9.3 偏好作用范围

支持：

### 全局默认偏好

- 默认回答风格。
- 默认回答深度。
- 默认语言。
- 默认自定义指令。

新对话自动继承全局偏好。

### 对话级偏好

新对话继承全局设置。

用户可以单独修改某个对话的默认偏好。

该对话后续继续使用自己的偏好。

### 单次提问偏好

单次提问可以覆盖当前偏好，不改变全局设置和对话默认设置。

不开放完整 System Prompt 编辑功能。

# 13. REST API 设计要求

## 13.1 基本要求

提供基础 REST API。

前端页面也通过 REST API 与后端通信。

未来支持个人 Python 程序和其他客户端调用。

统一 API 版本前缀：

`/api/v1/...`

重大不兼容变更时引入 `/api/v2/...`。

## 13.2 API 功能范围

至少支持：

- PDF 上传。
- 文档列表查询。
- 文档解析状态查询。
- 文档重新解析。
- 文档删除。
- 知识库统计。
- RAG 问答。
- 流式回答。
- 来源引用查询。
- 历史对话查询。
- 对话管理。

## 13.3 API 文档

使用 FastAPI 自动生成 Swagger/OpenAPI 文档。

支持：

- 在线查看接口。
- 查看请求参数。
- 查看请求示例。
- 查看响应结构。
- 在线调试。

不开发独立 SDK 或开发者门户。

## 13.4 API 安全与限流

支持：

- 基础接口访问认证。
- 基础权限校验。
- 问答、上传等关键接口限流。
- 请求频率和并发限制。

超限时返回 HTTP 429，并提供明确错误信息。

不建设按客户端管理配额的页面。

## 13.5 幂等性

关键 API 需要支持幂等性，至少包括：

- PDF 上传。
- 解析任务创建。
- RAG 问答提交。
- 重新解析。
- 文档删除。

防止网络重试和重复点击造成重复任务或重复 Token 消耗。

可采用：

- `Idempotency-Key`。
- 数据库唯一约束。
- Kafka 唯一任务 ID。
- Worker 状态校验。

不能依赖 Kafka 本身保证业务只执行一次。

## 13.6 请求追踪

每次 API 请求生成唯一 `request_id`。

贯穿：

- FastAPI。
- Query Rewrite。
- Elasticsearch。
- RRF。
- LLM API 调用。
- 错误日志。

支持通过 `request_id` 查询一次请求的处理记录。

不建设完整可视化链路追踪平台。

建议区分：

| ID | 用途 |
|---|---|
| request_id | API 请求 |
| conversation_id | 对话 |
| message_id | 消息 |
| task_id | 异步任务 |

# 14. 文件存储与系统配置

## 14.1 文件存储

第一版文件系统存储放在 Mac 本地。

SQLite 保存文件路径及关联信息。

文件存储需要通过业务层抽象，降低未来迁移到服务器的改造成本。

文件存储内容包括：

- 用户上传 PDF。
- MinerU 解析结果。
- PDF 提取图片。
- 用户上传图片。

用户图片、PDF 图片和临时文件必须采用独立的生命周期管理。

## 14.2 系统配置

系统配置统一在后端配置文件中维护。

包括：

- MinerU 连接配置。
- Kafka 连接配置。
- Elasticsearch 连接配置。
- LLM API 配置。
- Embedding 模型配置。
- Worker 并发参数。
- 任务超时时间。
- 临时文件清理周期。
- 其他运行参数。

不提供网页动态修改运行参数的功能。

修改配置后重启相关服务生效。

不支持配置导入和导出。

## 14.3 临时文件清理

支持定期自动清理：

- MinerU 解析过程中的中间文件。
- 上传过程中产生的临时缓存。
- 其他不再需要的系统临时文件。

清理周期和保留时间由后端配置文件固定维护。

不得删除正在被任务使用的文件，也不得误删需要长期保存的业务数据。

# 16. 非功能需求

## 16.1 稳定性

- 上传成功后必须正确创建解析任务。
- Kafka 消息处理需要考虑重复消费。
- 文档删除后不得被旧任务重新写入。
- 重新解析失败不得破坏旧版本。
- 清空知识库时不得出现残留的可检索数据。
- 对话删除时需要清理关联图片。
- LLM 调用失败需要保留已生成的部分内容。

## 16.2 安全性

- API Key 等敏感配置只保存在后端。
- 不在前端暴露模型密钥。
- 不在日志和检索详情中暴露敏感 Prompt 或 API Key。
- 后端对上传文件进行校验。
- 关键操作需要进行权限检查。
- 关键操作需要支持幂等处理。

## 16.3 可维护性

- 核心业务模块保持合理分层。
- API、业务逻辑、数据访问和后台任务职责分离。
- Elasticsearch 索引操作与文档业务生命周期保持一致。
- 外部服务调用封装为独立接口。
- 为后续更换模型、增加 Reranker 和引入 Redis 保留扩展空间。

## 16.4 可观测性

- 记录关键操作日志。
- 记录 API 失败及关键异常。
- 记录任务执行情况。
- 通过 `request_id` 追踪请求。
- 提供服务健康状态页面。
- 提供基础统计。

# 18. 第一版核心验收目标

第一版至少需要完成以下端到端业务场景。

## 场景一：PDF 上传与解析

1. 用户上传一个或多个 PDF。
2. 后端保存 PDF。
3. SQLite 创建文档记录。
4. 自动创建 Kafka 解析任务。
5. Worker 消费任务。
6. MinerU 完成解析。
7. 保存文本、页面结构和图片。
8. 将文本及向量写入 Elasticsearch。
9. 文档状态更新为 completed。

## 场景二：多模态 RAG 问答

1. 用户输入问题。
2. 用户可以附带图片。
3. 系统读取历史对话。
4. 执行 Query Rewrite。
5. Elasticsearch 执行 BM25 和 Dense Vector 检索。
6. RRF 融合并筛选 Top 5。
7. 获取关联 PDF 图片。
8. 组合上下文。
9. 调用 DeepSeek Flash。
10. 流式返回图文回答。
11. 展示 PDF 来源引用。

## 场景三：重新解析

1. 用户选择重新解析 PDF。
2. 创建新版本解析任务。
3. 旧版本继续参与检索。
4. 新版本解析成功。
5. 原子切换当前有效版本。
6. 清理旧版本文件和索引。

如果新版本失败，旧版本继续可用。

## 场景四：删除 PDF

1. 用户删除文档。
2. 系统处理关联解析任务。
3. 删除原始 PDF。
4. 删除解析结果和提取图片。
5. 删除 ES 对应索引数据。
6. 防止正在运行的任务重新写入。
7. 确保该文档不再出现在检索结果中。

## 场景五：历史对话管理

1. 创建新对话。
2. 进行多轮问答。
3. 保存消息和图片。
4. 支持编辑、重试和删除。
5. 支持历史搜索。
6. 支持 Markdown 导出。
7. 删除对话时清理关联图片。
