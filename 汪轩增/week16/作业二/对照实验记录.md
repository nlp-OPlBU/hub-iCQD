# 作业二：确定性脚本与无脚本效果对照

## 1. 实验问题

验证 ESG 招投标 Skill 工作流中，确定性代码是否能改善重复公告去重、金额单位换算和固定统计；同时观察关键词主题标签会不会漏掉语义相关公告。

## 2. 实验材料与方法

- **样本窗口：**2024-11-26 至 2026-11-26。
- **样本：**7 条可公开追溯的招标、中标或合同公告，另人为重复放入江苏同一公告 1 次，故输入共 8 行。
- **来源：**政府采购/公共资源交易平台，以及采购项目正式公告页。每条原文链接保存在 [`data/tender_sample.json`](data/tender_sample.json)。样本用于演示流程，不代表两年市场全量数据。
- **无脚本基线：**人工按原始字段逐行核查，先识别同源重复公告，再将明确披露金额换算成人民币元，按人工语义口径统计主题。
- **有脚本组：**将完全相同的 JSON 输入交给 [`scripts/esg_pipeline.py`](scripts/esg_pipeline.py)，输出保存于 [`results/script_output.md`](results/script_output.md)。脚本做字段清理、重复行合并、词表主题匹配、金额解析及固定汇总。
- 两组均使用相同的原始公告事实。脚本组的关键词表为确定性规则，不提供网页抓取、原文核验或语义推理。

## 3. 对照结果

| 指标 | 人工/Skill 无脚本基线 | 脚本结果 | 对照结论 |
|---|---:|---:|---|
| 输入行数 | 8 | 8 | 相同输入 |
| 去重后公告数 | 7 | 7 | 脚本按完全相同标题及链接自动去掉重复行 |
| 可解析金额 | 6 | 6 | 金额单位均成功转换为元 |
| 已披露金额合计 | 60,195,860元 | 60,195,860元 | 与人工核算一致；仅对样本且不代表市场总额 |
| 中位数 | 4,853,930元 | 4,853,930元 | 与人工核算一致 |
| 公告类型 | 中标5、合同1、招标1 | 中标5、合同1、招标1 | 类型计数一致 |
| 碳管理相关项目 | 7 | 7 | 加入“碳排放”等同义项后，初筛覆盖本样本相关项目 |
| 双碳/碳市场主题 | 人工复核7条均属相关主题 | 词表命中5条 | 脚本漏掉2条只写“碳排放核查”的公告，需扩充词表或人工复核 |

## 4. 结果解释

脚本最明显的收益是把去重、金额换算和重复统计变成了可重复执行的步骤。输入不变时，输出统计相同，也更容易审计计算来源。它减少了人工手算和复制表格时的算术/重复计数风险。

脚本的主题分类是词面规则：即使标题没有出现“碳市场”“双碳”这些词，碳排放核查仍可能实质上属于相关业务。实验中江苏和陕西核查项目没有被“双碳”关键词组命中，显示单纯确定性规则可能造成漏报。Skill/Agent 需要查阅原文、结合服务范围做语义筛选，再把判定结果和证据交给代码统计。

“有脚本”并不自动意味着信息更准确。金额解析假定未写币种的数字为人民币，不能判断预算、最高限价、合同额和中标额之间的含义；多标包项目还可能出现总额与分包金额重复相加。当前输入字段把人工校验后的金额放在 `amount`，正式扩大样本时应增加 `amount_kind`、`currency`、`package_id`、`source_type` 等字段，并按统计口径分组。

## 5. 结论

这组样本支持一个有限结论：**确定性脚本适合处理标准化、去重、单位换算和描述统计；语义相关性、来源可信度与金额性质仍需 Skill/人工审查。**样本只有 7 条公告，且不是盲测或全量爬取，不能据此推断脚本在所有 ESG 项目上的准确率，也不报告虚构的时间节省比例。

## 6. 复现方法

在项目根目录运行：

```powershell
python 作业二/scripts/esg_pipeline.py 作业二/data/tender_sample.json -o 作业二/results/script_output.md
```

先由 Skill 搜索并核验原文，把结果按 JSON 字段整理；再运行脚本生成统计稿。收到脚本输出后，抽查重复项、主题标签、金额类型和原文链接，再写结论。
