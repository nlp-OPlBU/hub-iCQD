# ESG 招投标监测

使用可用的互联网搜索工具自主发现公告、核实来源、去重并形成结构化分析。区分招标/采购公告、中标/成交公告、意向公开和新闻报道。新闻不能替代公告证据。

## 搜集与判断

1. 默认历史窗口为截至检索日往前两年，日报只收录自上次成功检查后发布的新公告。注明窗口和时区；无上次记录时使用用户指定起点或最近24小时，并披露。
2. 多轮检索主题词及同义词，覆盖 ESG、可持续发展、双碳、碳达峰/中和、碳核算/盘查/核查、产品碳足迹、绿色供应链、环境社会治理等。按平台和地区补充查询，不能仅凭搜索摘要断定穷尽。
3. 优先政府采购、公共资源交易、央国企/采购单位官方平台及正式公告原文。每条记录保留标题、采购单位、地区、公告类别、发布时间、项目金额/预算/中标金额、币种、供应商、主题、原文链接、检索词和核验状态。
4. 仅当项目核心交付确属 ESG/可持续/双碳时纳入主统计。边缘相关项目放入待复核或排除，并说明理由。合并相同项目在多个平台的转载；不同标包要按公告口径处理。
5. 明确区分预算、最高限价、合同估算价和中标/成交金额。金额未知时记为 null，不推算；框架协议、单价合同、跨年合同、多个标包及含税口径不可直接与普通总价混算。
6. 对关键公告打开原文核验，记录网页可访问性及证据强弱。使用脚本整理记录时，人工复核主题误判、项目重复、金额口径和异常值。

## 输出

历史分析应说明覆盖范围、检索日期、纳入/排除口径、记录数、金额披露率，并分析项目主题热点、地区/采购方分布和金额分布。金额统计单独披露金额缺失数量；不能把公开样本说成全市场。每日摘要列出新增项目、公告类别、采购方、地区、关键时间/金额、主题和原文链接；无新增时明确写“本轮未发现符合条件的新公告”。

定时搜索与主动推送需要外部调度器和用户可用的交付渠道。Skill 本身只规定执行方法；未配置调度时，不得声称已持续监控或已发送日报。

用户提供或授权的记录可整理为 `作业二/scripts/esg_pipeline.py` 接受的 JSON 输入。统计结果应作为核验辅助，不替代公告原文判断。
