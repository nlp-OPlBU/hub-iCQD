# ESG 月报（轻量版 · 无脚本）

这是 `esg-monthly-report` 的最小版本：**只有这个文件，没有脚本、没有配置、没有缓存。**
模型自己搜索、自己筛选、自己写。

## 何时用这个版本

- 环境里不能跑 Python，或不想装依赖；
- 只要一份能看的初稿，不要求逐条可追溯；
- 客户/行业与默认示例差别很大，懒得改配置。

如果要求「每条结论能点回原文」「同一输入重跑结果一致」「金额/日期零错误」，
请用脚本版 `esg-monthly-report`。

## 流程（一次对话内完成）

### 1. 锁定四个板块

默认客户：中国神华（煤炭开采 + 煤电一体化）。四个板块固定为：

| 板块 | 检索方向 | 建议查询 |
| --- | --- | --- |
| 政策标准 | 披露准则、碳市场、碳关税、国际谈判 | `财政部 可持续披露准则 <月份>`、`全国碳市场 配额方案 <年份>`、`CBAM <年份>`、`COP31` |
| 行业实践 | 煤炭/能源行业 ESG、评价与指数 | `煤炭行业 ESG 蓝皮书 <年份>`、`能源上市公司 ESG 评价 <年份>` |
| 公司动态 | 神华 ESG、经营、评级、绿色项目 | `中国神华 ESG <月份>`、`中国神华 三季报 <年份>`、`中国神华 MSCI ESG 评级` |
| 对标企业 | 陕煤、中煤、兖矿、国家能源集团 | `陕西煤业 ESG <年份>`、`中煤能源 ESG <年份>`、`兖矿能源 ESG <年份>` |

每个板块至少 3 条查询，日期词必须带上月份或年份——这是控制时效的唯一手段。

### 2. 硬性筛选规则（照做，不要跳）

1. **只要报告期内有明确发布日期的条目**写进「本月动态」；日期不明或更早的只能进「背景」并注明。
2. **同一事件多源转载只留一条**，优先官方（公司官网、部委、交易所、评级机构），其次主流财经媒体。
3. **剔除**招聘、培训课程、文库、论文、广告、聚合页。
4. **抓不到正文时只引用标题与摘要**，不得扩写细节、不得推断数字。
5. **金额、评级、政策名称**必须与原文一致；找不到就写「未披露」。

### 3. 输出结构（直接照此写）

```
# {客户} ESG 月报 · {年}年{月}月刊
## 本期判断
一句话结论 + 3—5 条要点（每条后可附来源链接）
## 一、政策、标准与评级动态
每条：日期 / 事实 / 对客户的影响 / 影响等级（高中低）/ 来源
## 二、行业动态与最佳实践
趋势 2—3 条 + 对标案例表（企业 / 行动 / 结果 / 启示）
## 三、公司动态与 ESG 影响
动态 3—5 条 + 评级快照 + 经营数据
## 四、对标企业关键行动
1—3 家，每家一句话行动 + 一句启示
## 五、风险雷达
表格：风险 / 等级 / 触发信号 / 建议动作
## 六、行动建议
30 天 / 90 天 / 180 天，各 2—3 条，必须可执行
## 七、下月关注清单
## 附录：来源清单
编号 / 日期 / 来源 / 标题（带链接）
```

### 4. 交付前自检（逐条回答，全部为「是」才算完成）

- [ ] 每条「本月动态」都有明确日期，且落在报告期内？
- [ ] 有没有把去年的旧闻写进本月？（抽查 3 条往回查原文日期）
- [ ] 同一事件是否出现两次（不同媒体转载）？
- [ ] 所有金额单位统一（万元/亿元），没有元与万元混用？
- [ ] 每个判断都能落到一个具体来源，而不是「据报道」？
- [ ] 每条政策/行业动态都回答了「对客户意味着什么」？
- [ ] 评级信息是否注明口径（哪家机构、哪天、第几名）？
- [ ] 样本不足时，是否在方法说明里写清偏差？

## 已知局限（用之前先接受）

| 项 | 表现 |
| --- | --- |
| 覆盖不稳定 | 搜什么取决于临场发挥，换一次对话结果就不同 |
| 易漏/易重 | 无 URL 去重，同一条新闻可能被算两次 |
| 数字风险 | 日期取错（截止日当发布日）、金额单位错、评级记错 |
| 不可复现 | 无法解释「为什么这次是 21 条、上次是 35 条」 |
| 规模受限 | 超过 30 条来源后，上下文里容易丢条目 |

实测对照：同一个招标任务，无脚本版识别出约 24 条含金额记录、出现 2 组重复、9 条日期缺失；
脚本版处理 76 条候选、抽出 34 条含金额记录、0 重复、4 条日期缺失且被显式标注。
详见仓库内《作业2_有script_vs_无script_对比》。

## 一句话总结

SKILL.md 决定「怎么想、怎么写」；脚本决定「找得全不全、算得对不对」。
只要初稿，这个文件够了；要能交付给客户的报告，建议用脚本版。
