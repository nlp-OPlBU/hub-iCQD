# 作业 2：有确定性 script vs 无 script 的效果对比

> 对比对象：ESG 招标情报任务（同一问题、同一天、同一模型）
> A 组：纯提示 / 自由检索（无脚本）　B 组：本仓库 skill + 确定性脚本
> 结论先行：**脚本不负责“想”，负责“不漏、不重、不算错”；模型负责“读懂、判断、建议”。两者叠加的效果显著优于任一方单独使用。**

---

## 1. 实验设计

为了公平，两组使用**同一批公开检索结果**（2026-11-25 当日的搜索引擎返回），只改变“处理方式”：

| | A 组：无脚本 | B 组：Skill + Script |
|---|---|---|
| 检索 | 模型自由拟词、逐条浏览 | 11 条固定检索式（赛道 × 年份），结果写缓存 |
| 记录 | 模型在上下文中摘抄 | 正则抽取 + 结构化 JSON |
| 去重 | 人工判断 | URL + 标题相似度 + 项目名/金额三级去重 |
| 统计 | 模型心算/口算 | Python `statistics` 计算并落盘 |
| 报告 | 模型直接写 | 模型写洞察，脚本渲染 HTML/图表 |
| 复现 | 不能 | 同输入重跑结果一致 |

## 2. 量化对比

| 指标 | A 组 无脚本 | B 组 有脚本 | 差异 |
|---|---|---|---|
| 原始结果处理量 | 38 条，人工逐条阅读 | 77 条候选 → 76 条结构化记录 | B 组吞吐高 2 倍 |
| 识别出“含明确金额”的记录 | 约 24 条（人工判断，易漏） | 34 条（正则抽取，可复核） | +42% |
| 重复记录 | 2 组重复、5 处同项目多源 | 0（脚本去重） | 消除重复计价风险 |
| 缺失日期 | 9 条 | 4 条（且自动标注） | 缺口可见 |
| 采购人缺失 | 难以逐条核对 | 58 条（76%）→ 复核后补齐 29 条 | 人工复核聚焦 76% 缺口 |
| 金额单位错误 | 元/万元/亿元混用，易错 | 统一折算为万元 | 0 单位错误 |
| 统计口径 | 每次不同 | 固定公式：合计/均值/中位/P25/P75 | 可审计 |
| 算术错误 | 人工汇总，难保证 | 0 | — |
| 报告生成耗时 | 无法复现（依赖对话轮次） | 1.4 s（分析+渲染） | 秒级 |
| 结果可复现 | 否 | 是（缓存 + 固定输入） | 关键差异 |

> 注：A 组“约 24 条”来自同一批 38 条结果的逐条人工筛选；B 组 34 条为脚本抽取后仍保留低置信标记的记录，最终人工复核入样 32 条。

## 3. 五个真实翻车案例（以及脚本如何兜住）

### 3.1 日期被“截止日”带偏

生态环境部一条公告正文写着“2026 年 11 月 30 日前完成核查”，但实际发布日期是 **2026-02-09**。
- 无脚本：模型容易把 11-30 当成“本月新闻”，造成月报虚增。
- 有脚本：`collect.py` 取搜索结果中**最后一个日期**作为发布日，并保留 `in_window` 标记；该条被正确归为背景。

### 3.2 金额被“服务费”带偏

北京市发改委 ESG 评估项目真实中标金额 **47.80 万元**，页面里同时出现“中标服务费 1500 元”。
- 无脚本：直接摘“1500 元”，量级错 300 倍。
- 有脚本：优先匹配“中标（成交）金额”并允许括号单位 `47.80（万元）`；首轮仍抓到 1500 元，复核时被 `confidence` 标记暴露并修正——说明**脚本 + 复核**才可靠，裸脚本也会错。

### 3.3 同一项目被多源重复计价

“中国神华 ESG 咨询 168 万元”在国能 e 招、新浪财经、企业观察网、华盛通、启信宝出现 5 次。
- 无脚本：汇总时极易算成 840 万元。
- 有脚本：按“项目名 + 金额”去重，只保留官方公告一条。

### 3.4 单位混用

同一批数据里同时出现 `28000.00 元`、`2.8 万元`、`￥1,672,680`、`16800000`。
- 无脚本：心算易错，且无法解释口径。
- 有脚本：统一折算并保留 `amount_raw` 原文，报告只出现万元/亿元。

### 3.5 分类被供应商名字带偏

“国投丰乐 ESG 专项报告编制”因中标方叫“博奕方略**企业管理咨询**有限公司”，被误分到“管理咨询”。
- 无脚本：分类不稳定，换一次表述就变。
- 有脚本：改为**标题优先**分类，标题无信号再看正文；并把“专项报告/报告编制”加入报告类词典。

## 4. 效果差异的本质

| 能力 | 模型（无脚本） | 脚本 | 组合 |
|---|---|---|---|
| 发现新角度、提出假设 | 强 | 无 | 强 |
| 固定覆盖、不漏赛道 | 弱（依赖临场发挥） | 强 | 强 |
| 精确抽取金额/日期 | 中（易幻觉） | 强（可复核） | 强 |
| 去重、单位归一 | 弱 | 强 | 强 |
| 统计与图表 | 弱（易算错） | 强 | 强 |
| 可复现、可审计 | 弱 | 强 | 强 |
| 判断“这意味着什么” | 强 | 无 | 强 |

一句话：**脚本把“事实层”钉死，模型才有余力做“判断层”。**

---

## 5. 什么时候不要脚本

- 早期探索、选题发散：先让模型自由检索，找到值得追踪的赛道，再固化成检索式；
- 一次性冷门问题：写脚本的成本高于直接读三篇文章；
- 需要读 PDF/图片/复杂表格：脚本抽取会失真，应让模型读原文 + 人工复核。

本项目的做法是“先探索、后固化”：先用自由检索找到 8 大赛道与关键玩家，再写进 `config/queries.yaml`，之后每月/每天自动跑。

## 6. 本项目的脚本清单（确定性部分）

| 脚本 | 确定性职责 | 输出 |
|---|---|---|
| `web.py` | 多引擎检索、正文抽取、缓存、限流冷却、导入通道 | 统一 JSON |
| `collect.py`（月报） | 固定检索式、去重、信源分级、时效打分、抓正文 | `evidence.json` |
| `extract.py` | 金额/日期/采购人/供应商/赛道正则抽取 | 结构化记录 |
| `analyze.py` | 合计/均值/中位/分位/区间/年度/赛道/区域/TOP | `tender_stats.json` + HTML |
| `watch.py` | 增量 diff、日报、状态持久化 | `daily_watch_*.md` |
| `render.py`（月报） | KPI、证据分布图、时间轴、来源表 | 月报 HTML/MD |

所有脚本只依赖 `requests / beautifulsoup4 / lxml / pyyaml`，无外部服务、无数据库。

## 7. 迭代记录（v1 → v2）

| 问题（v1） | 现象 | 修复（v2） |
|---|---|---|
| 检索被限流 | Quark 触发验证码后整轮为空 | 引擎轮询 + 18 秒短冷却 + 退避重试 + 相关性闸门 + 导入通道 |
| 搜狗跳转链接 | 94 条结果全是 sogou 跳转页 | 从 `pcurl` 参数还原真实 URL，并过滤 360 的 `so.com/link` |
| 字符级去重过严 | 不同标题被误判重复，公司板块只剩 5 条 | 改为字符二元组 Jaccard，阈值 0.86 |
| 日期错位 | 正文截止日被当发布日 | 取结果中最后一个日期 + 保留 `in_window` 标记 |
| 金额括号 | `47.80（万元）` 抽取失败 | 正则允许数字与单位间出现括号/空白 |
| 分类偏移 | 供应商名含“管理咨询”导致误分类 | 标题优先分类 + 扩充报告类词典 |
| 供应商抽取 | ccgp 表格中抓到“94.0” | 组织名正则 + 黑名单 + 表格行回退 |
| 图表裁切 | 柱顶数值被 SVG 顶边切掉 | 增大顶部留白；0 值不画柱 |
| 对比度不足 | 11px 灰字对比度 2.5:1 | 次级文本统一加深到 ≥4.5:1 |
| 统计口径不一 | 月度/年度混算 | 固定 `analyze.py` 公式，报告注明口径 |

## 8. 最终结论

1. **有脚本的版本不是“更自动”，而是“更可信”**：同一条“3537.6 万元、中位 66.6 万元”的结论，脚本可以逐条回溯到 32 个 URL，无脚本做不到。
2. **脚本不会替代判断**：本月“平台+零碳占 59%、报告编制红海化”的判断，仍来自模型对结构化数据的解读。
3. **最佳实践是混合**：脚本负责检索/抽取/统计/渲染，模型负责复核异常、解释原因、给出行动建议；再用 `confidence` 与 `method_note` 把不确定性显式写出来。
