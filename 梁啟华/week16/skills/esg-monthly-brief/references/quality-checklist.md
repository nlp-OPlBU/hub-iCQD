# 质量门判定标准（quality-checklist）

交付前逐条自检。任一条 FAIL，必须先返工；确实无法满足时，在“数据缺口与声明”中写明原因。

| # | 质量门 | 判定标准 | 不通过时 |
| --- | --- | --- | --- |
| 1 | `transmission_judgment_present` | “政策与标准”中每一条都有【变化→作用机制→对客户影响→可观测信号】，且不是“利好/利空”式空话 | 补写传导链；无法判断则降级为“待观察”并说明 |
| 2 | `peer_cases_decomposable` | 每个案例都含“问题/做法/投入与成果/可复制条件”四要素 | 换案例或补充拆解，禁止只写新闻摘要 |
| 3 | `tension_identified_or_explicitly_cleared` | 至少 1 个有证据的张力；或显式写“未识别到显著张力”+检索依据 | 补证据；无证据不得编造 |
| 4 | `sources_cited` | 每条结论附来源（名称+日期+链接，或名称+日期）；全文可核验来源 ≥5 条 | 补来源；二手来源回溯原文 |
| 5 | `no_fabricated_data` | 无占位符（待补充/XXX/TBD/TODO），无无来源数字；推断已标注 | 删除或标注；无法核实的数据写入缺口 |
| 6 | `tracking_points_falsifiable` | 恰好 ≥3 个跟踪点，每个含“时间窗 + 具体信号 + 验证方式 + 判定规则” | 改写为可证伪表述 |

## 机器校验

```bash
python -I scripts/check_brief.py <简报.md>
```

脚本可自动检查：结构完整性、传导判断关键词、案例四要素、跟踪点数量与要素、来源链接数量、
占位符。**“数据真实性”只能人工判断**，脚本通过不代表事实无误。

## 人工终检（30 秒）

1. 只看标题能否说出本月最重要的一件事？
2. 每条政策后面是否都有一句“所以客户要做什么/注意什么”？
3. 跟踪点下个月是否真的能被验证？
4. 有没有任何数字无法回溯到来源？
