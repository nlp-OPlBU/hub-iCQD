# 服务类型分类体系（service-taxonomy）

每条招标/中标记录必须有**且只有一个主标签**，可有 0-3 个副标签。主标签用于统计，
副标签用于检索与交叉分析。

## 判定优先级

同一项目命中多类时，按下列顺序确定主标签（越靠前优先级越高）：

1. 交付物动词优先：`核查/审验/核算` → 2；`报告编制/鉴证` → 3；`平台/系统/软件` → 6；
   `培训` → 5；`认证/审核/评价` → 7；`债券/贷款评估认证` → 8；`CCER/交易` → 4；其余 → 1。
2. 命中关键词数量多者优先；
3. 仍相同，按上表编号小者优先（与 `keyword-rules.json` 的 `service_types` 顺序一致）。

## 主/副标签规则

- 主标签唯一，不得为空；无法判断时填 `other`（中文“其他/待定”），并在报告中单列“待人工复核”。
- 副标签取其余命中类别，最多 3 个；主标签不得同时出现在副标签中。
- 一条记录不得因为“看起来像”而被强分类；以文本证据为准。

## 统计口径

- 服务类型占比以**主标签**计，分母为去重后的项目数（不是金额）。
- 金额分布按服务类型分别统计时，只统计 `amount_basis != unknown` 的记录，
  并在图表/表格脚注注明“已知金额项目 N 个，占比 X%”。
- 同一项目跨年度续约视为两个项目（以项目编号/公告日期区分），但在供应商格局分析中可合并统计。

## 未知与复核

```text
service_type = other
service_subtypes = []
review_note = "关键词未覆盖：<摘要 30 字>"
```

每期报告末尾列出 `other` 数量与占比；若超过 10%，需回补关键词库。
